# 한글 짜임 — 글자꼴을 만들기 전에 알아야 할 것

첫 판을 만들고 나서 ㅞ 가 무너지고 획이 글자틀을 삐져나온 까닭을 찾다가,
한글 짜임을 제대로 모르고 짰다는 걸 알았다. 공부한 것과 그에 따라 바꾼
구조를 여기에 적는다.

## 1. 첫 판이 틀린 지점

**자모를 "임의의 상자에 넣고 늘이는" 방식이었다.**

```
중성 자리 = (0.56, 0.38, 1.00, 1.00)   ← 기둥이 y 0.38 에서 잘린다
가로요소  = (0.00, 0.00, 1.00, 0.33)   ← 기둥 밑을 가로지른다
```

겹모음은 이 상자를 또 쪼갰다. ㅞ 는 `ㅜ + ㅔ` 이고 ㅔ 는 다시 `ㅓ + ㅣ` 라서,
상자가 두 번 쪼개지며 기둥이 토막나고 길이가 제각각이 됐다. 글자가 아니라
부스러기가 된다.

**획을 자르는 선을 상자 밖에 뒀다.**

ㅅ·ㅈ·ㅊ 은 사선을 꼭지 위로 넘겨 긋고 잘라내는데, 자르는 선을
`(X0 - 2w, Y0 - w, X1 + 2w, Y1)` 로 뒀다. 그래서 다리가 제 상자 아래로
획 굵기만큼(34), 좌우로 12씩 **삐져나왔다.** 측정값이다.

## 2. 한글의 짜임

### 모아쓰기와 여섯 짜임

한 음절은 초성 + 중성 (+ 종성) 을 한 칸에 모아 쓴다. 중성의 성격과 받침
유무가 짜임을 가른다.

| | 민글자 (받침 없음) | 받침글자 |
|---|---|---|
| **가로모임** 기둥이 오른쪽 (ㅏㅐㅑㅒㅓㅔㅕㅖㅣ) | 가 개 거 | 간 갠 건 |
| **세로모임** 가로줄기가 아래 (ㅗㅛㅜㅠㅡ) | 고 교 구 | 곤 굔 군 |
| **섞임모임** 둘이 섞임 (ㅘㅙㅚㅝㅞㅟㅢ) | 과 괘 궤 | 관 괜 궨 |

### 벌 — 같은 낱자라도 자리마다 다르게 그린다

조합형 글꼴의 고전 규격인 **8×4×4** 는 초성 8벌, 중성 4벌, 종성 4벌을 둔다.
([iolo/8x4x4-fonts](https://github.com/iolo/8x4x4-fonts))

**초성 8벌**

| 벌 | 짝이 되는 중성 | 받침 |
|---|---|---|
| 1 | ㅏㅐㅑㅒㅓㅔㅕㅖㅣ | 없음 |
| 2 | ㅗㅛㅡ | 없음 |
| 3 | ㅜㅠ | 없음 |
| 4 | ㅘㅙㅚㅢ | 없음 |
| 5 | ㅝㅞㅟ | 없음 |
| 6 | 세로모음 전부 | 있음 |
| 7 | ㅗㅛㅜㅠㅡ | 있음 |
| 8 | 섞임모음 전부 | 있음 |

**2벌(ㅗㅛㅡ)과 3벌(ㅜㅠ)이 갈리는 까닭**이 중요하다. ㅗ 는 짧은기둥이
**위로** 올라와 초성을 밀어내지만, ㅜ 는 **아래로** 내려가므로 초성이 더
내려앉을 수 있다. 같은 세로모임이라도 초성의 자리가 달라야 한다.
첫 판은 이 둘을 같게 취급했다.

**중성 4벌** — 초성이 ㄱ·ㅋ 인지와 받침 유무로 가른다.
**종성 4벌** — 중성이 오른쪽을 얼마나 차지했는지로 가른다.

| 벌 | 짝이 되는 중성 |
|---|---|
| 1 | ㅏㅑㅘ |
| 2 | ㅓㅕㅚㅝㅟㅢㅣ |
| 3 | ㅐㅒㅔㅖㅙㅞ |
| 4 | ㅗㅛㅜㅠㅡ |

출처는 벌을 가르는 **규칙**만 적고 그 **까닭**은 적지 않았다. 위의 ㅗ/ㅜ
설명은 내가 형태에서 끌어낸 것이다.

### 조형 용어와 규칙

- **기둥** — 모음의 세로줄기. 글자꼴의 최소 조형단위.
- **곁줄기** — ㅏㅓㅑㅕ 의 짧은 가로줄기. 초성 모양에 흔들리지 않고
  **글자틀 중앙의 무게중심선을 기준으로** 놓인다.
- **이음줄기** — ㄴㄷㄸㄹㅌㅍ 의 아래 가로줄기. **ㅓ·ㅕ 와 만날 때는 기둥에서
  떼어야 한다.** 붙이면 곁줄기와 헷갈린다.
- **속공간** — 획이 둘러싼 빈 공간. 닫힌속공간(ㅇㅎㅁㅂ)과 열린속공간.
  닿자·홀자의 자리뿐 아니라 글자 폭에도 영향을 받는다.

([속공간](https://ko.wikipedia.org/wiki/%EC%86%8D%EA%B3%B5%EA%B0%84) ·
[타입확대경 #22 이음줄기](https://typographyseoul.com/%ED%83%80%EC%9E%85%ED%99%95%EB%8C%80%EA%B2%BDtype-loupe-22-%EC%9D%B4%EC%9D%8C%EC%A4%84%EA%B8%B0/) ·
[한글 디지털 바탕체 조형요소 연구](http://koreantypography.org/wp-content/uploads/thesis/kst_j1_4.pdf))

> 뒤의 두 자료는 이 세션의 네트워크에서 열리지 않아 검색 결과에 인용된
> 부분까지만 읽었다. 전문을 보면 더 정확히 맞출 수 있다.

## 3. 새 구조

`hangul.py` 가 자리표를, `render.py` 가 그리기를 맡는다.

### 원칙

1. **기둥은 언제나 글자틀 높이를 끝까지 지난다.** 섞임모임에서도 자르지 않는다.
2. **가로줄기는 기둥 앞에서 끝난다.** 기둥 밑을 가로지르지 않는다.
3. **곁줄기 높이는 글자틀 기준으로 고정이다.**
4. **모든 요소는 제 자리를 벗어나지 않는다.** 자르는 선은 반드시 제 상자.
5. **초성 8벌, 종성 4벌.** 모음 무리마다 자리와 크기를 따로 준다.

### 모음을 상자가 아니라 요소로 적는다

```python
'ㅔ': dict(kind='V', stems=[0.74, 0.96], bars=[(-1, 0.50)], reach=0.52, cho_r=0.44)
'ㅞ': dict(kind='M', h='ㅜ', v='ㅔ')
```

`stems` 는 기둥의 x 자리(글자틀 비율)다. 몇 개든 **세로로 끝까지 선다.**
`bars` 는 곁줄기의 (방향, 높이). 방향 `-1` 은 왼쪽으로 `reach` 까지,
`+1` 은 오른쪽 끝까지, `0` 은 기둥끼리 잇는다.

섞임모임은 세로요소를 그대로 쓰고, 가로요소의 줄기를 **세로요소 먹물의
왼쪽 끝에서 `M_GAP` 만큼 물러난 곳에서 끊는다.** 초성은 그 끊긴 자리까지를
제 폭으로 받는다.

ㅞ 의 결과:

```
기둥   x 0.76, y 0.00~1.00      ← 끝까지 선다
기둥   x 0.98, y 0.00~1.00
곁줄기 x 0.54~0.76, y 0.50
가로줄기 x 0.04~0.48, y 0.32    ← 곁줄기(0.54) 앞에서 끊긴다
짧은기둥 x 0.26, y 0.128~0.32
초성   (0.04, 0.44) ~ (0.48, 1.00)
```

## 4. 확인

- 낱자가 제 상자를 벗어나는 경우: **ㅇ·ㅎ 뿐** (원의 오버슈트, 의도한 것)
- 11,172자 전수 조립: **빈 글자 0 · 글자틀 이탈 0**

## 5. 남은 일

- 섞임모임 받침글자(뭱·궷 같은 것)는 초성 자리가 많이 좁다. 실제 글꼴도
  좁지만, 쓸 만한지 더 봐야 한다.
- 중성 4벌 중 "초성이 ㄱ·ㅋ 일 때" 규칙은 아직 넣지 않았다.
- 이음줄기를 ㅓ·ㅕ 앞에서 떼는 규칙은 지금 구조에서는 초성과 모음이 다른
  칸에 있어 저절로 지켜지지만, 칸 사이 간격이 충분한지 눈으로 봐야 한다.

# 2차 — Pretendard 실측으로 비례 다시 잡기

"여러 모음을 쓸 때 따로따로 노는 느낌", "자음과 모음 사이가 좁다" 는 지적을
받고 Pretendard Regular 을 받아 **픽셀로 떠서 실측**했다. 추측으로 맞추던 값을
전부 실측값으로 바꿨다.

## 재는 방법

폰트를 캔버스에 큰 크기로 그리고 픽셀을 읽어, **연결 성분**으로 초성·중성·종성
덩어리를 갈라 각 상자를 쟀다. 자폭(1770 유닛)을 1 로 두고 정규화했다.
대체 폰트를 재는 사고를 막으려고 `measureText` 로 자폭이 1770/2048 과 맞는지
먼저 확인했다.

## 드러난 잘못 넷

**1. 글자가 납작했다.** Pretendard 의 한글은 먹물이 0.95w × 1.00h 로 거의
정사각인데, 내 것은 0.86 × 0.74 였다. 게다가 렌더러가 가로는 860, 세로는 744 로
**비균등 축소**를 하고 있어서 세로가 한 번 더 눌렸다.

**2. 자폭이 1em 이었다.** Pretendard 는 0.864em(1770/2048) 을 쓴다. 같은 글자
크기에서 내 글자가 15% 더 크고 글줄이 그만큼 벌어졌다. 띄어쓰기에도 자폭을
통째로 줘서 낱말 사이가 세 배였다. → 자폭 880, 띄어쓰기 300.

**3. 초성이 글자틀을 세로로 꽉 채웠다.** Pretendard 의 초성은 0.19~0.89 만 쓴다.

**4. 섞임모임에서 초성을 작은 상자에 가뒀다.** Pretendard 는 섞임모임에서도
초성 폭을 0.51 (기둥 둘이면 0.43) 로 유지한다. 초성이 쪼그라들면 왼쪽이 비어
글자가 한 덩어리로 안 읽힌다. "따로따로 노는" 원인이 이것이었다.

## 실측값과 옮긴 규칙

| | Pretendard | 적용 |
|---|---|---|
| 초성 폭 | 기둥 1개 0.51 · 2개 0.43 | 모음마다 `cho_r` 로 |
| 초성 세로 (민글자) | 0.101~0.805 | 그대로 |
| 초성 세로 (받침글자) | 0.294~0.835 | 받침 높이 + 0.025 ~ 0.845 |
| 기둥 | ㅏ 0.774 · ㅣ 0.826 · ㅓ 0.827 | 그대로 |
| 두 기둥 | ㅐ 0.629/0.854 · ㅔ 0.646/0.858 | 그대로 |
| 초성–중성 틈 | 가 0.172 · 기 0.208 · 개 0.114 | 0.197 / 0.209 / 0.137 |

**받침 높이가 획 수를 따라 달라지고, 기둥 바닥이 그 높이를 따라간다.**

| 받침 | 꼭대기 | 기둥 바닥 |
|---|---|---|
| ㄹ | 0.355 | 0.402 (+0.047) |
| ㅂ | 0.324 | 0.369 (+0.045) |
| ㅁ | 0.296 | 0.342 (+0.046) |
| ㄱ | 0.274 | 0.319 (+0.045) |

네 단계(0.352 / 0.325 / 0.296 / 0.268)로 묶고 `기둥 바닥 = 받침 꼭대기 + 0.045`,
`초성 바닥 = 받침 꼭대기 + 0.025` 로 넣었다.

## Pretendard 와 다르게 간 곳

- **아래로 내려가는 짧은기둥(ㅜㅠ)과 받침.** Pretendard 는 받침 윗부분이 열린
  것(ㅂ ㄴ)에 기대 짧은기둥을 그대로 내려보내고, 막힌 받침(ㄷ ㄹ ㅇ ㅌ)에서는
  아예 붙여버린다. 낱자를 조합해 만드는 글꼴에서는 위험해서, 받침이 있으면
  가로줄기를 올리고 짧은기둥을 짧게 해 떼어 뒀다.
- **ㅅ·ㅈ·ㅊ 초성 + ㅛ·ㅠ.** 짧은기둥이 둘이면 ㅅ 의 벌어진 다리와 부딪힌다.
  짧은기둥이 하나(ㅗㅜ)일 때만 아래가 열린 초성이 옆으로 내려오게 했다.
- **섞임모임의 왼쪽 곁줄기(ㅝㅞ).** 초성의 내려오는 다리를 가로지르므로,
  가로줄기와 초성 사이 빈 띠의 한가운데에 적응적으로 놓는다.

## 확인

`check.py` 가 다각형 교집합으로 전수 검사한다. 상자(bbox)로 재면 '고' 의 ㄱ 과
ㅗ 의 짧은기둥처럼 상자만 겹치고 먹물은 닿지 않는 경우를 다 잡아내 쓸모가 없다.

- **11,172자 — 먹물 겹침 0 · 자폭 이탈 0**

## 남은 숙제

- **획 굵기.** 12px 에서 내 획은 0.41px, Pretendard 는 0.91px 이다. 모노라인을
  지키면서 작은 글씨를 읽히게 하려면 굵기를 올려야 한다.
- 중성 4벌 중 "초성이 ㄱ·ㅋ 일 때" 규칙은 아직 넣지 않았다.
