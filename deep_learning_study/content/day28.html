• 학습이 안 될 때 따라가는 체계적인 디버깅 절차를 익힌다.
  • 학습률 찾기, 워밍업, 코사인 감쇠 등 학습률 스케줄의 원리를 이해한다.
  • 하이퍼파라미터 탐색 우선순위와 방법(무작위 탐색 등)을 안다.
  • 혼합 정밀도, 기울기 누적, 체크포인팅 등 메모리·속도 최적화를 사용한다.
  • 실험 관리와 모델 평가·배포의 기본을 안다.
👨‍🏫 교과서에 없는 것들 논문은 성공한 결과만 보여 줍니다. 그 뒤에는 NaN, 꿈쩍 않는 손실, 이유 모를 성능 저하와 씨름한 수백 번의 실험이 있습니다. 오늘은 그 "숨은 노동"을 줄이는 노하우를 모았습니다. 캡스톤을 시작하기 전에 꼭 읽고, 캡스톤 중에 막히면 다시 돌아오세요.

1. 디버깅 레시피: 작게 시작해서 키워라

Karpathy의 "A Recipe for Training Neural Networks"를 바탕으로 한 순서입니다. 한 번에 하나씩만 바꾸세요.

  1. 데이터부터 본다: 학습 전에 샘플 수십 개를 눈으로 보세요. 레이블이 맞는지, 전처리 후 이미지가 이상하지 않은지(정규화, 채널 순서, 회전), 클래스 분포는 어떤지.
  2. 바보 같은 베이스라인: 항상 최빈 클래스를 예측하는 모델, 선형 모델. 내 신경망은 최소한 이것보다 좋아야 합니다.
  3. 초기 손실 확인: 분류면 $\ln K$ 근처여야 합니다(Day 9). 출력층 편향을 클래스 사전확률로 초기화하면 더 좋습니다.
  4. 배치 하나 과적합: 샘플 몇 개(배치 하나)로만 학습시켜 손실이 거의 0이 되는지 확인하세요. 이것도 안 되면 버그입니다(모델이 데이터를 볼 수 없거나, 손실·레이블이 잘못됨).
  5. 전체 데이터로 과적합: 규제 없이 충분히 큰 모델로 학습 정확도를 높일 수 있는지 확인.
  6. 규제: 그다음에 검증 성능을 위해 증강, 드롭아웃, 가중치 감쇠, 조기 종료를 추가.
  7. 튜닝: 학습률 → 스케줄 → 배치 크기 → 모델 크기 순.
# "배치 하나 과적합" 테스트: 모든 새 프로젝트의 첫 실험
xb, yb = next(iter(train_dl))
xb, yb = xb[:16].to(device), yb[:16].to(device)
model.train()
for i in range(300):
    loss = loss_fn(model(xb), yb)
    opt.zero_grad(); loss.backward(); opt.step()
    if i % 50 == 0: print(i, loss.item())

3. 학습률: 가장 중요한 하이퍼파라미터

학습률 찾기 (LR range test)

학습률을 아주 작은 값(1e-7)에서 큰 값(10)까지 지수적으로 키우며 몇백 스텝 학습하고 손실을 기록합니다. 손실이 가장 가파르게 떨어지는 구간의 학습률, 혹은 손실이 최소인 지점의 약 1/10을 고릅니다.

import numpy as np
import matplotlib.pyplot as plt
rng = np.random.default_rng(0)
# 간단한 로지스틱 회귀로 LR range test 시연
X = rng.normal(size=(2000, 20)); w_true = rng.normal(size=20); y = (X @ w_true + rng.normal(0, .5, 2000) > 0).astype(float)
w = np.zeros(20); lrs = np.logspace(-4, 1.5, 300); losses = []
for i, lr in enumerate(lrs):
    bi = rng.integers(0, 2000, 64); p = 1 / (1 + np.exp(-np.clip(X[bi] @ w, -30, 30)))
    losses.append(-np.mean(y[bi] * np.log(p + 1e-9) + (1 - y[bi]) * np.log(1 - p + 1e-9)))
    w -= lr * X[bi].T @ (p - y[bi]) / 64
sm = np.convolve(losses, np.ones(10) / 10, mode='same')
plt.figure(figsize=(7, 3.3)); plt.semilogx(lrs, sm); plt.ylim(0, 2)
plt.xlabel('학습률'); plt.ylabel('손실(평활)'); plt.title('LR range test: 손실이 폭발하기 직전보다 한참 작은 값을 고른다'); plt.show()

스케줄

  • 워밍업: 처음 몇 백~몇 천 스텝 동안 학습률을 0에서 목표값까지 선형으로 올립니다. 초기에는 Adam의 2차 모멘트 추정이 부정확하고 가중치가 무작위라 큰 업데이트가 위험합니다. Transformer 학습에 거의 필수입니다.
  • 코사인 감쇠: 이후 코사인 곡선을 따라 서서히 줄입니다. 후반의 작은 학습률이 손실 지형의 좁은 골짜기 바닥으로 들어가게 해 줍니다.
  • Step decay: 특정 에폭마다 1/10. 고전적인 CNN 방식.
  • ReduceLROnPlateau: 검증 손실이 정체되면 줄임.
steps = np.arange(5000); warm = 300; lr_max, lr_min = 3e-4, 3e-5
def warmup_cosine(s):
    if s < warm: return lr_max * (s + 1) / warm
    r = (s - warm) / (len(steps) - warm); return lr_min + 0.5 * (lr_max - lr_min) * (1 + np.cos(np.pi * r))
step_decay = lambda s: lr_max * (0.1 ** (s // 2000))
plt.figure(figsize=(7, 3)); plt.plot([warmup_cosine(s) for s in steps], label='워밍업 + 코사인'); plt.plot([step_decay(s) for s in steps], label='step decay')
plt.xlabel('step'); plt.ylabel('lr'); plt.legend(); plt.show()

배치 크기와 학습률: 배치를 $k$배 키우면 학습률도 대략 $k$배(SGD) 또는 $\sqrt k$배(Adam) 키우는 것이 출발점입니다(선형 스케일링 규칙). 단, 아주 큰 배치는 일반화가 약간 나빠질 수 있습니다.

4. 하이퍼파라미터 탐색

우선순위하이퍼파라미터
1 (가장 중요)학습률
2학습률 스케줄, 학습 길이(에폭/스텝)
3가중치 감쇠, 드롭아웃, 증강 강도
4배치 크기, 모델 크기(깊이/너비)
5Adam β, ε, 초기화 세부
  • 격자 탐색보다 무작위 탐색: 중요한 하이퍼파라미터는 소수이므로, 무작위로 뽑으면 중요한 축을 더 다양하게 탐색합니다(Bergstra & Bengio, 2012).
  • 학습률·가중치 감쇠는 로그 스케일로 뽑으세요(1e-5 ~ 1e-2).
  • 처음엔 넓게, 짧게(몇 에폭) 탐색하고, 좋은 구간에서 좁게, 길게.
  • 도구: Optuna(베이지안 최적화 + 조기 중단), W&B Sweeps.

5. 메모리와 속도

혼합 정밀도 (Mixed precision)

대부분의 연산을 16비트로 하면 메모리가 절반, 최신 GPU에서 속도가 2~3배입니다. bf16은 fp32와 지수 범위가 같아 오버플로 걱정이 거의 없고(A100 이상, 최근 GPU), fp16은 범위가 좁아 손실 스케일링이 필요합니다(T4 등).

scaler = torch.amp.GradScaler("cuda")                  # fp16일 때만 필요
for xb, yb in train_dl:
    with torch.autocast(device_type="cuda", dtype=torch.float16):   # bf16 가능하면 torch.bfloat16
        loss = loss_fn(model(xb), yb)
    opt.zero_grad()
    scaler.scale(loss).backward()                       # 작은 기울기가 0으로 사라지지 않게 키워서 역전파
    scaler.unscale_(opt); torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
    scaler.step(opt); scaler.update()

기울기 누적 (Gradient accumulation)

GPU 메모리에 배치 256이 안 들어가면, 배치 64로 4번 순전파·역전파해서 기울기를 누적한 뒤 한 번 업데이트합니다. Day 10의 "기울기는 누적된다"를 이용하는 것입니다.

accum = 4
for i, (xb, yb) in enumerate(train_dl):
    loss = loss_fn(model(xb), yb) / accum               # 평균을 맞추기 위해 나눔
    loss.backward()                                      # 기울기가 .grad에 누적
    if (i + 1) % accum == 0:
        opt.step(); opt.zero_grad()

기타

  • 활성화 체크포인팅: 순전파 때 일부 활성화를 저장하지 않고 역전파 때 다시 계산. 메모리 ↓, 시간 약 30% ↑.
  • torch.compile(model): 그래프 최적화로 속도 향상(PyTorch 2.x).
  • FlashAttention: F.scaled_dot_product_attention이 자동으로 사용(Day 24).
  • 분산 학습: 여러 GPU면 DDP(데이터 병렬), 모델이 GPU 하나에 안 들어가면 FSDP/ZeRO(파라미터 분할).

6. 평가와 배포의 기본

  • 평가 지표를 먼저 정하라: 정확도? F1? AUC? 상위 5개 정확도? 비즈니스 목표와 맞아야 합니다.
  • 오류 분석: 틀린 샘플을 직접 보고 유형을 분류하세요. 레이블 오류가 생각보다 많습니다.
  • 보정(Calibration): 모델이 90% 확신한 예측이 실제로 90% 맞는지. 신경망은 과신하는 경향이 있습니다(온도 스케일링으로 보정).
  • 추론 최적화: model.eval() + torch.inference_mode(), 양자화(int8), ONNX/TorchScript 내보내기.
  • 재현성 기록: 코드 버전(git 커밋), 데이터 버전, 하이퍼파라미터, 시드, 환경(라이브러리 버전).
