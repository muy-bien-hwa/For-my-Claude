• Dataset과 DataLoader로 데이터를 표본 단위로 정의하고 미니배치로 공급할 수 있다.
  • 학습 함수와 평가 함수를 학습·평가 모드, 기울기 기록, 가중 평균까지 올바르게 쓸 수 있다.
  • 혼합 정밀도의 원리(16비트 형식의 범위와 정밀도, 손실 스케일링)를 설명하고 적용할 수 있다.
  • 체크포인트로 최고 모델을 저장하고, 중단한 학습을 똑같이 이어 갈 수 있다.
  • 이후 강의에서 쓸 재사용 가능한 학습 템플릿을 완성할 수 있다.

Colab에서 노트북 열기

Dataset

Dataset 클래스는 두 가지만 정한다: 표본이 몇 개인가(__len__), i번째 표본은 무엇인가(__getitem__). 데이터 전체를 메모리에 올릴 필요가 없다. __getitem__이 불릴 때 파일 하나를 읽어 전처리해 돌려주면 된다.

class TensorPairDataset(Dataset):
    def __init__(self, X, y, transform=None):
        self.X, self.y, self.transform = X, y, transform

    def __len__(self):
        return len(self.X)

    def __getitem__(self, i):
        x = self.X[i]
        if self.transform:
            x = self.transform(x)        # 꺼낼 때마다 전처리(증강이면 매번 다르게)
        return x, self.y[i]

Fashion-MNIST

Fashion-MNIST는 쇼핑몰 상품 사진을 MNIST와 같은 형식(28×28 흑백, 학습 6만·테스트 1만, 10클래스)으로 만든 데이터셋이다. 형식이 같아 MNIST 코드를 그대로 쓸 수 있으면서 훨씬 어렵다. MNIST에서 98%를 넘는 다층 퍼셉트론이 여기서는 90% 근처에 머문다.

torchvision.datasets.FashionMNIST가 내려받기와 해시 확인을 해 준다. transform에는 표본을 꺼낼 때마다 적용할 전처리를 넣는다. ToTensor는 PIL 이미지(0~255)를 (1, 28, 28) 텐서(0~1)로 바꾸고, Normalize는 학습 데이터의 평균 0.2860과 표준편차 0.3530으로 표준화한다.

tf = transforms.Compose([transforms.ToTensor(),
                         transforms.Normalize((MEAN,), (STD,))])
train_full = torchvision.datasets.FashionMNIST("data", train=True, transform=tf)
test_set = torchvision.datasets.FashionMNIST("data", train=False, transform=tf)
train_set, val_set = random_split(train_full, [54000, 6000],
                                  generator=torch.Generator().manual_seed(0))

random_split은 학습 데이터를 학습 54,000장과 검증 6,000장으로 나눈다. 시드를 준 Generator를 넘겨야 실행할 때마다 같은 분할이 나온다.

DataLoader

DataLoader는 Dataset에서 표본을 꺼내 미니배치로 묶는다. 배치 크기가 128이면 dataset[i]를 128번 불러 (1, 28, 28) 텐서 128개를 쌓아 (128, 1, 28, 28) 텐서를 만든다. 학습 데이터 54,000장이면 한 에폭이 $\lceil 54000/128 \rceil = 422$배치다.

인자뜻보통 값
batch_size배치 크기학습 32~512, 평가는 메모리가 허락하는 만큼 크게
shuffle에폭마다 순서를 섞는다학습만 True
num_workers표본을 준비하는 별도 프로세스 수CPU 코어 수 근처 (Colab은 2)
pin_memoryCPU → GPU 복사를 빠르게 하는 고정 메모리GPU를 쓸 때 True
drop_last마지막의 작은 배치를 버린다배치 정규화가 크기 1 배치를 피하려면 True
generator섞는 순서를 정하는 난수 생성기재현하려면 시드를 준다

num_workers가 0이면 학습 루프가 표본 준비를 직접 하느라 GPU가 기다린다. 1 이상이면 별도 프로세스가 다음 배치들을 미리 준비한다. 이미지 파일을 읽어 증강하는 무거운 전처리일수록 차이가 크다. 데이터가 작고 전처리가 가벼우면 35일차처럼 전체를 GPU 텐서 하나로 올려 두고 인덱스로 잘라 쓰는 편이 가장 빠르다.

학습 함수와 평가 함수

def train_one_epoch(model, loader, opt, loss_fn, scaler, sched=None):
    model.train()                       # 드롭아웃·배치 정규화를 학습 모드로
    tot_loss, correct, n = 0.0, 0, 0
    for xb, yb in loader:
        xb, yb = xb.to(device, non_blocking=True), yb.to(device, non_blocking=True)
        with torch.autocast(device.type, dtype=amp_dtype):   # 혼합 정밀도
            out = model(xb)
            loss = loss_fn(out, yb)
        opt.zero_grad(set_to_none=True)
        scaler.scale(loss).backward()
        scaler.step(opt)
        scaler.update()
        if sched is not None:
            sched.step()                                # 스텝마다 바뀌는 스케줄
        tot_loss += loss.item() * len(yb)               # 표본 수로 가중
        correct += (out.argmax(1) == yb).sum().item()
        n += len(yb)
    return tot_loss / n, correct / n


@torch.inference_mode()                                 # 기울기 기록 끄기
def evaluate(model, loader, loss_fn):
    model.eval()                        # 드롭아웃 끄기, 이동 평균 통계 쓰기
    tot_loss, correct, n = 0.0, 0, 0
    for xb, yb in loader:
        xb, yb = xb.to(device), yb.to(device)
        with torch.autocast(device.type, dtype=amp_dtype):
            out = model(xb)
        tot_loss += loss_fn(out.float(), yb).item() * len(yb)
        correct += (out.argmax(1) == yb).sum().item()
        n += len(yb)
    return tot_loss / n, correct / n
  1. 모드 전환. model.train()과 model.eval()을 함수 첫 줄에서 부른다. 평가 함수가 끝나도 모드는 바뀐 채로 남으므로, 학습 함수도 매번 자기 모드를 다시 정한다.
  2. 기울기 기록 끄기. torch.inference_mode()는 no_grad()보다 조금 더 빠른 평가 전용 모드다. 모드 전환(eval)과는 별개이므로 둘 다 필요하다.
  3. 가중 평균. 마지막 배치는 작을 수 있으므로(54,000 = 128 × 421 + 112) 배치 평균을 그냥 평균하면 안 된다. 배치 손실에 표본 수를 곱해 더한 뒤 전체 표본 수로 나눈다.
  4. 장치 이동. non_blocking=True와 pin_memory=True를 함께 쓰면 복사와 계산이 겹쳐 진행된다.
  5. .item()의 비용. GPU 값을 CPU로 가져오면서 GPU가 일을 마칠 때까지 기다린다. 아주 빠른 학습에서는 손실을 GPU 텐서로 모았다가 에폭 끝에 한 번 꺼낸다.

혼합 정밀도

32비트 부동소수점 대신 16비트로 계산하면 메모리가 절반이 되고, GPU의 텐서 코어가 행렬곱을 몇 배 빠르게 한다(T4는 32비트 8 TFLOP/s, 16비트 텐서 코어 65 TFLOP/s). 하지만 16비트는 표현할 수 있는 범위나 정밀도가 좁다. 혼합 정밀도는 행렬곱과 합성곱만 16비트로 계산하고, 합·소프트맥스·손실처럼 오차에 민감한 연산과 가중치 갱신은 32비트로 해 두 장점을 함께 얻는다.

float16의 문제는 범위다. 깊은 신경망의 기울기에는 $10^{-6}$ 이하의 작은 값이 많은데, float16으로는 이런 값이 정밀도를 잃거나 0이 된다(언더플로). 그래서 GradScaler는 역전파 전에 손실에 큰 수(예: $2^{16}$)를 곱해 기울기를 표현 가능한 범위로 올리고, 갱신 전에 다시 그 수로 나눈다. 곱한 수가 너무 커서 기울기에 inf가 생기면 그 스텝을 건너뛰고 곱하는 수를 줄인다. bfloat16은 범위가 넓어 스케일러가 필요 없다. 최신 GPU(A100 이후)와 TPU는 bfloat16을 쓰고, Colab의 T4는 float16을 쓴다.

amp_dtype = torch.float16 if use_cuda else torch.bfloat16
scaler = torch.amp.GradScaler("cuda", enabled=use_cuda)   # float16일 때만 켠다
with torch.autocast(device.type, dtype=amp_dtype):
    loss = loss_fn(model(xb), yb)
scaler.scale(loss).backward()      # 손실 × S로 역전파
scaler.step(opt)                   # 기울기를 S로 나눠 갱신 (inf가 있으면 건너뜀)
scaler.update()                    # S 조절

체크포인트와 조기 종료

체크포인트는 학습 도중의 상태를 저장한 파일이다. 두 가지 용도가 있다. 검증 성능이 가장 좋았던 시점의 모델을 남겨 두는 것, 그리고 중단된 학습(Colab의 연결 끊김 등)을 이어 가는 것이다. 이어 가려면 모델만으로는 부족하다.

저장할 것빠뜨리면
모델 state_dict가중치가 없다
옵티마이저 state_dict모멘텀과 Adam의 이동 평균이 0부터 다시 시작해 학습이 흔들린다
스케줄러, GradScaler학습률이 처음 값으로 돌아간다
에폭, 기록어디서부터 몇 에폭 더 할지 모른다
난수 상태 (torch.get_rng_state(), DataLoader의 생성기)드롭아웃 마스크와 데이터 순서가 달라져 결과를 재현하지 못한다

재현성

27일차의 원칙을 PyTorch에 적용하면 다음과 같다.

  1. 시드. random.seed, np.random.seed, torch.manual_seed(CPU와 모든 GPU)를 함께 고정한다.
  2. 데이터 순서와 분할. DataLoader와 random_split에 시드를 준 Generator를 넘긴다. num_workers가 1 이상이면 각 프로세스의 시드는 이 생성기에서 정해진다.
  3. 결정적 연산. GPU의 일부 연산은 빠른 대신 실행마다 결과가 미세하게 다르다. torch.use_deterministic_algorithms(True)는 결정적 알고리즘만 쓰게 하지만 느려질 수 있고, 결정적 구현이 없는 연산은 오류를 낸다. torch.backends.cudnn.benchmark = True는 입력 크기에 맞는 가장 빠른 합성곱 알고리즘을 골라 빠르게 하는 대신 재현성을 해친다.
  4. 보고. 시드를 고정해도 결론은 시드 여러 개로 확인한다(27일차).

기록

에폭마다 학습·검증 손실과 정확도, 학습률을 사전에 모아 두고 끝나면 그린다. 규모가 커지면 TensorBoard(torch.utils.tensorboard)나 Weights & Biases 같은 도구가 기록을 파일이나 웹에 남겨 여러 실험을 비교하게 해 준다. 무엇을 기록할지는 27일차의 목록(손실, 지표, 학습률, 기울기 노름, 갱신 비율)을 따른다.

정리

  • Dataset = __len__ + __getitem__(+ transform). DataLoader = 섞기, 묶기, 병렬 준비.
  • 학습 함수: train() → 장치 이동 → autocast 순전파 → zero_grad → 스케일된 backward → step → 스케줄러. 평가 함수: eval() + inference_mode(). 지표는 표본 수로 가중 평균.
  • 혼합 정밀도: 행렬곱은 16비트, 민감한 연산은 32비트. float16은 GradScaler로 언더플로를 막는다.
  • 체크포인트: 모델·옵티마이저·스케줄러·스케일러·에폭·기록·난수 상태. 최고 검증 모델로 테스트한다.

연습 문제

  1. 폴더 data/고양이/*.jpg, data/개/*.jpg에서 이미지를 읽는 Dataset을 쓰라. 레이블은 폴더 이름(고양이 0, 개 1)이고, 이미지는 PIL.Image.open으로 연다.
    풀이
    class FolderDataset(Dataset):
    def __init__(self, root, transform=None):
        self.items = [(p, k) for k, name in enumerate(["고양이", "개"])
                      for p in sorted(glob.glob(f"{root}/{name}/*.jpg"))]
        self.transform = transform
    def __len__(self):
        return len(self.items)
    def __getitem__(self, i):
        path, label = self.items[i]
        img = Image.open(path).convert("RGB")       # 꺼낼 때 읽는다
        return (self.transform(img) if self.transform else img), label

    torchvision.datasets.ImageFolder가 같은 일을 한다(34일차).

  2. 혼합 정밀도에서 기울기 클리핑(24일차)을 하려면 scaler.step(opt) 전에 scaler.unscale_(opt)를 먼저 불러야 한다. 이유는?
    풀이

    역전파된 기울기는 손실에 곱한 스케일 S만큼 커져 있다. 그대로 노름을 재어 자르면 기준값(예: 1)이 S배 커진 기울기에 적용되어 사실상 클리핑이 안 된다. unscale_로 원래 크기로 되돌린 뒤 clip_grad_norm_을 하고, scaler.step은 이미 되돌린 것을 알고 다시 나누지 않는다.

  3. 검증 정확도가 가장 높은 시점과 검증 손실이 가장 낮은 시점이 다를 수 있다. 어느 쪽으로 최고 모델을 고를지 26일차의 결과를 떠올리며 논하라.
    풀이

    26일차 프로젝트에서 검증 손실로 멈추면 너무 일찍 멈춰 정확도가 낮았다. 손실은 틀린 표본에 대한 과신에 민감해서 정확도가 계속 오르는 동안에도 커질 수 있다. 최종 목표 지표(여기서는 정확도)로 고르는 것이 보통이다. 확률 자체가 중요하면(보정, 위험 예측) 손실로 고른다.
