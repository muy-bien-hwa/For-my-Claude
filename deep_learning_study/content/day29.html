• PyTorch 텐서를 만들고 형상·자료형·장치를 다루며 NumPy 배열과 오갈 수 있다.
  • autograd가 계산 그래프를 실행하면서 기록하고 역전파하는 방식을 19일차의 Value 엔진과 비교해 설명할 수 있다.
  • nn.Module로 모델을 정의하고 파라미터, state_dict, 학습·평가 모드를 다룰 수 있다.
  • 손실 함수와 옵티마이저로 표준 학습 단계(zero_grad → 순전파 → 손실 → backward → step)를 쓸 수 있다.
  • 28일차의 NumPy MLP를 PyTorch로 옮기고, 출력과 기울기가 같음을 검증할 수 있다.

왜 프레임워크인가

3, 4주차에는 순전파와 역전파를 손으로 유도해 NumPy로 구현했다. 원리를 이해하는 데는 그 방법이 가장 좋지만, 새 층을 넣을 때마다 역전파를 다시 유도하고 기울기 검증을 해야 한다. 계산도 CPU 한 대에서만 돈다. PyTorch는 이 일을 대신한다. 텐서 연산을 GPU에서 실행하고, 계산 그래프를 기록해 기울기를 자동으로 구하며, 층·손실·옵티마이저·데이터 도구를 제공한다.

torch.from_numpy(배열)과 텐서.numpy()는 메모리를 공유한다. 한쪽을 바꾸면 다른 쪽도 바뀐다. torch.tensor(배열)은 복사한다. NumPy의 기본 실수형은 float64이므로, 신경망에 넣기 전에 .float()로 float32를 만든다.

GPU

GPU는 단순한 연산기 수천 개를 동시에 돌린다. 행렬곱처럼 같은 연산을 많은 원소에 반복하는 계산에 강하다. Colab의 T4 GPU는 32비트 연산 기준 최대 초당 약 8조 번(8 TFLOP/s), 16비트 텐서 코어로는 약 65 TFLOP/s를 처리한다. Colab의 CPU 2개는 초당 수십억~수백억 번 수준이다.

  1. 장치를 정한다. device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
  2. 모델과 데이터를 같은 장치로 옮긴다. model.to(device), xb.to(device). 장치가 다른 텐서끼리 연산하면 오류가 난다.
  3. 옮기는 횟수를 줄인다. CPU와 GPU 사이의 복사는 연산보다 느리다. 손실 값을 매 스텝 .item()으로 꺼내는 것도 복사다.
  4. 시간을 잴 때는 기다린다. GPU 연산은 비동기로 실행된다. 명령을 보내고 바로 다음 줄로 넘어가므로, torch.cuda.synchronize()로 끝나기를 기다린 뒤 시간을 잰다.

노트북 2절은 2048 × 2048 행렬곱을 CPU와 GPU에서 재어 비교한다. 런타임을 T4 GPU로 바꾸고 직접 재어 본다.

자동 미분

requires_grad=True인 텐서로 계산하면, PyTorch는 각 연산의 결과에 그 연산을 거꾸로 계산하는 함수(grad_fn)를 붙여 계산 그래프를 기록한다. backward()를 부르면 그래프를 거꾸로 따라가며 연쇄법칙을 적용하고, 결과를 잎 텐서의 .grad에 더한다. 19일차에 만든 Value 엔진과 같은 알고리즘이다.

19일차의 뉴런 예제($s = w_1x_1 + w_2x_2 + b$, $L = -\log\sigma(s)$)를 PyTorch로 계산하면 Value 엔진과 같은 값이 나온다.

vals = (2.0, -1.0, -3.0, -2.0, -3.0)
w1, x1, w2, x2, b = (torch.tensor(v, requires_grad=True) for v in vals)
s = w1 * x1 + w2 * x2 + b
L = -torch.log(torch.sigmoid(s))
L.backward()

L = 0.3133, ∂w1 = 0.2689, ∂x1 = -0.5379, ∂w2 = 0.5379, ∂x2 = 0.8068, ∂b = -0.2689

기울기는 누적된다

backward()는 .grad에 값을 더한다. 같은 그래프 구조를 세 번 역전파하면 기울기가 세 배가 된다. 18일차에 본 것처럼 한 변수가 여러 곳에 쓰일 때 기울기를 더해야 하므로 이렇게 설계되었다. 그래서 학습 루프는 매 스텝 기울기를 0으로 지운다.

w = torch.tensor(1.0, requires_grad=True)
for k in range(3):
    (3 * w).backward()
    print(f"{k + 1}번째 backward 뒤 w.grad = {w.grad.item()}")

1번째 backward 뒤 w.grad = 3.0
2번째 backward 뒤 w.grad = 6.0
3번째 backward 뒤 w.grad = 9.0

기록 끄기

평가와 파라미터 갱신은 미분할 필요가 없다. with torch.no_grad(): 안의 계산은 그래프를 만들지 않아 메모리와 시간을 아낀다. x.detach()는 그래프에서 떼어 낸 텐서를 돌려준다. 자동 미분만으로 쓴 선형 회귀 학습 루프는 다음과 같다. 기울기는 PyTorch가 구하고, 갱신과 초기화는 직접 한다.

w = torch.zeros(1, requires_grad=True)
b = torch.zeros(1, requires_grad=True)
for step in range(200):
    loss = ((X * w + b - Y) ** 2).mean()
    loss.backward()
    with torch.no_grad():          # 갱신은 기록하지 않는다
        w -= 0.1 * w.grad
        b -= 0.1 * b.grad
    w.grad.zero_()
    b.grad.zero_()

w = 2.949, b = 0.997, 손실 0.0712  (참값 w = 3, b = 1)

nn.Module

층과 모델은 모두 nn.Module을 상속한다. __init__에서 층을 속성으로 만들면 그 파라미터가 자동으로 모델에 등록되고, forward에 계산을 쓴다. 모델을 함수처럼 호출하면(model(x)) forward가 실행된다. backward는 쓰지 않는다.

class MLP(nn.Module):
    def __init__(self, sizes=(784, 256, 128, 10), p_drop=0.0):
        super().__init__()
        self.fc1 = nn.Linear(sizes[0], sizes[1])
        self.fc2 = nn.Linear(sizes[1], sizes[2])
        self.fc3 = nn.Linear(sizes[2], sizes[3])
        self.drop = nn.Dropout(p_drop)

    def forward(self, x):
        x = self.drop(F.relu(self.fc1(x)))
        x = self.drop(F.relu(self.fc2(x)))
        return self.fc3(x)          # 로짓. 소프트맥스는 손실 함수 안에서

model = MLP()
for name, p in model.named_parameters():
    print(f"{name:12s} {tuple(p.shape)}")

파라미터 수는 28일차의 NumPy 모델과 같은 235,146개다. nn.Linear의 가중치는 (출력, 입력) 형상으로 저장되고 $xW^\top + b$를 계산한다. 우리 NumPy 구현의 (입력, 출력) 형상과 전치 관계다. 층을 순서대로 지나가기만 하면 될 때는 nn.Sequential(nn.Linear(784, 256), nn.ReLU(), ...)로 짧게 쓴다.

state_dict

모델의 파라미터와 버퍼(배치 정규화의 이동 평균 등)를 이름-텐서 사전으로 담은 것이 state_dict다. torch.save(model.state_dict(), "m.pt")로 저장하고, 같은 구조의 모델에 model.load_state_dict(torch.load("m.pt"))로 불러온다. 21일차에 직접 만든 저장 방식과 같은 생각이다. nn.Sequential의 키는 '0.weight', '0.bias', '2.weight', ...처럼 층 번호가 붙는다.

학습 모드와 평가 모드

드롭아웃과 배치 정규화는 학습과 평가에서 다르게 동작한다. model.train()과 model.eval()이 모든 하위 층의 모드를 바꾼다. 드롭아웃 0.5인 모델에 같은 입력을 두 번 넣으면 학습 모드에서는 출력이 다르고, 평가 모드에서는 같다.

학습 모드, 같은 입력 두 번: tensor([ 0.0187,  0.5781, -0.0442]) tensor([0.1345, 0.3773, 0.1225])
평가 모드, 같은 입력 두 번: tensor([ 0.0103,  0.3045, -0.0523]) tensor([ 0.0103,  0.3045, -0.0523])

nn.Linear의 기본 초기화는 균등분포 $U(-1/\sqrt{n_{\text{in}}},\ 1/\sqrt{n_{\text{in}}})$다. 입력이 784개면 표준편차가 0.0206으로, He 초기화(0.0505)의 약 0.41배다. 대부분은 이대로도 학습되지만, 24일차의 결과와 정확히 비교하려면 nn.init.kaiming_normal_(layer.weight, nonlinearity="relu")로 바꾼다.

손실 함수와 옵티마이저

nn.CrossEntropyLoss는 로짓과 정수 레이블을 받아 안에서 로그-소프트맥스를 안정적으로 계산한다(11일차). 모델 끝에 소프트맥스를 미리 씌우면 소프트맥스가 두 번 적용되어 손실과 기울기가 틀린다. 오류 없이 실행되므로 찾기 어려운 버그다(27일차).

logits = torch.tensor([[2.0, 0.5, -1.0], [0.1, 0.2, 3.0]])
labels = torch.tensor([0, 2])
loss_fn = nn.CrossEntropyLoss()
manual = -(logits.log_softmax(dim=1)[torch.arange(2), labels]).mean()
print(loss_fn(logits, labels), manual, loss_fn(logits.softmax(dim=1), labels))

표준 학습 단계

어떤 모델이든 학습 한 스텝은 다섯 줄이다. 순서를 외워 둔다.

optimizer.zero_grad()          # 1. 지난 스텝의 기울기 지우기
out = model(xb)                # 2. 순전파 (그래프 기록)
loss = loss_fn(out, yb)        # 3. 손실
loss.backward()                # 4. 역전파 (.grad 채우기)
optimizer.step()               # 5. 파라미터 갱신

옵티마이저는 torch.optim.SGD(model.parameters(), lr=0.1, momentum=0.9), torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=0.01)처럼 만든다. 파라미터마다 다른 설정을 주려면 그룹으로 나눈다. 28일차처럼 가중치 감쇠를 가중치에만 적용하는 예다.

decay = [p for p in model.parameters() if p.dim() >= 2]      # 가중치 행렬
no_decay = [p for p in model.parameters() if p.dim() < 2]    # 편향
opt = torch.optim.AdamW([{"params": decay, "weight_decay": 0.01},
                         {"params": no_decay, "weight_decay": 0.0}], lr=1e-3)

학습률 스케줄러

torch.optim.lr_scheduler에 계단, 코사인, 원사이클 등이 있다(23일차). LambdaLR은 "최대 학습률에 곱할 배율"을 스텝의 함수로 받아 어떤 모양이든 만들 수 있다. 스텝마다 바꿀 때는 optimizer.step() 다음에 scheduler.step()을 부른다. 1,000스텝 중 100스텝 워밍업 + 코사인이면 스텝 0, 99, 500, 999의 학습률이 다음과 같다(최대 $10^{-3}$).

스텝 0, 99, 500, 999의 학습률: ['2.00e-05', '1.00e-03', '5.85e-04', '0.00e+00']

Keras와의 대응

Keras는 같은 일을 더 짧게 쓴다. compile로 손실과 옵티마이저를 정하고 fit이 학습 루프를 대신 돈다. PyTorch는 학습 루프를 직접 쓰는 대신 그 안의 모든 단계를 바꿀 수 있다. 연구와 새 모델 구현에는 PyTorch가, 표준적인 모델을 빠르게 만들 때는 Keras가 편하다. Keras 3는 계산 엔진으로 TensorFlow, JAX, PyTorch를 고를 수 있다.

정리

  • 텐서는 형상·자료형·장치를 가진다. 이미지는 (N, C, H, W). from_numpy는 메모리를 공유한다.
  • 모델과 데이터는 같은 장치에. GPU 시간 측정은 synchronize 뒤에.
  • autograd: 순전파 때 그래프를 기록하고, backward()가 .grad에 더한다. 그래서 매 스텝 zero_grad().
  • nn.Module: __init__에 층, forward에 계산. state_dict로 저장. train()/eval()로 모드 전환.
  • CrossEntropyLoss에는 로짓을 넣는다. 학습 한 스텝 = zero_grad → 순전파 → 손실 → backward → step.

    x = torch.tensor(1.0, requires_grad=True); y = torch.tensor(2.0, requires_grad=True)

def fit(model, epochs=15, lr=1e-3, wd=0.01, bs=128, aug=True, seed=1):
    torch.manual_seed(seed)
    decay = [p for p in model.parameters() if p.dim() >= 2]
    no_decay = [p for p in model.parameters() if p.dim() < 2]
    opt = torch.optim.AdamW([{"params": decay, "weight_decay": wd},
                             {"params": no_decay, "weight_decay": 0.0}], lr=lr)
    steps = math.ceil(len(Xtr) / bs)
    sched = torch.optim.lr_scheduler.LambdaLR(opt, warmup_cosine(epochs * steps,
                                                                  steps))
    for ep in range(epochs):
        order = torch.randperm(len(Xtr))
        for s in range(0, len(Xtr), bs):
            idx = order[s:s + bs]
            xb = shift_batch(Xtr[idx]) if aug else Xtr[idx]
            xb, yb = xb.to(device), ytr[idx].to(device)
            opt.zero_grad()
            loss = F.cross_entropy(model(xb), yb)
            loss.backward()
            opt.step()
            sched.step()
    return model
